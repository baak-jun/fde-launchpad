# AI를 어떻게 운용했는지 보여주는 준비 체계

기준 출처는 사용자가 이 대화에서 제공한 Probe 설명이다. 기술·의도·인지 각 100점, FDE 소통 축의 배점은 미상으로 기록한다. 공식 공고와 점수 체계를 별도로 확인한 자료가 아니며 이 키트가 점수를 보장하거나 자동 채점하지 않는다.

## 4개 축과 실제 준비물

| 축 | 보여줄 행동 | 키트에 준비한 것 | 아직 사람이 해야 할 것 |
|---|---|---|---|
| 기술 관리 | 직접 실행·수정하고 실패를 재현 | 실행 앱, 버전 잠금, 테스트, 백업·복구, 도메인 팩 | 실제 문제의 정확성·성능·배포 조건 검증 |
| 의도 관리 | 목표·제약·완료 기준을 정하고 방향을 갱신 | INTENT 양식, 구현 프롬프트, 작업 계획, 결정 기록 | 실제 목표와 우선순위를 자기 언어로 결정 |
| 인지 관리 | 구조·근거·실패 지점을 설명하고 예측 | HOW_IT_WORKS, 한계 목록, 예측→실험 질문 | 코드를 열고 설명·수정·재현을 직접 수행 |
| 소통 | 다른 사람이 자연스럽게 이어받게 함 | HANDOFF, 시작 명령, 상태·증거·백업 위치 | 현재 프로젝트에 맞게 완료·미완료 사실 갱신 |

## 기술 관리는 이렇게 연습한다

`.venv/Scripts/python.exe scripts/verify.py`를 실행하고 테스트 이름만 읽지 말고 하나의 실패 조건을 선택한다. 예를 들어 승인 후 입력을 수정하고, 기존 승인으로 실행하면 409 오류가 나는지 확인한다. 보호 장치가 왜 필요한지 `runtime/store.py`의 revise/execute와 대응 테스트로 설명한다.

검증의 범위를 말할 수 있어야 한다. 이 키트에서 중복 방지가 확인된 대상은 같은 SQLite 트랜잭션 안의 로컬 기록이다. 이메일·결제 API와 DB는 한 트랜잭션이 아니므로 그 서비스의 멱등 키, 상태 조회, 재조정 로직이 따로 필요하다.

## 의도 관리는 이렇게 남긴다

프로젝트를 만들 때 `BRIEF.md`와 `INTENT.md`를 먼저 채운다. "좋은 서비스를 만들어줘" 대신 "문의 한 건을 분류하고 사람이 확인한 뒤 로컬 티켓 하나를 만들며, 승인 거부와 재시도 사례가 통과해야 한다"처럼 관찰할 수 있는 결과를 쓴다.

AI에게 작업을 맡길 때 입력 자료, 수정 가능 범위, 산출물, 합격 기준, 다음 작업과의 연결을 함께 준다. 방향이 바뀌면 이전 프롬프트를 누적하는 데 그치지 않고 유지할 조건과 폐기할 가정을 적는다. 실제로 위임하지 않은 작업을 위임했다고 꾸미거나 사후에 가짜 사고 과정을 작성하지 않는다.

현재 작업의 결정과 실제 실패는 [DECISIONS.md](DECISIONS.md)에 남겼다. 이 기록은 구현 선택의 근거이며 참가자 본인의 당시 의사결정을 대신 증명하지 않는다.

## 인지 관리는 이렇게 연습한다

`UNDERSTANDING.md`의 질문에 먼저 답하고 실행 결과와 비교한다. 다음 네 실험이 출발점이다.

1. "환불도 하고 로그인도 안 된다"를 넣으면 어떤 분류가 나올지 예측한다.
2. 승인한 요청을 수정한 뒤 어떤 상태와 버전이 남을지 예측한다.
3. 두 번 실행해도 왜 기록이 하나인지 DB 제약과 트랜잭션으로 설명한다.
4. 모델이 존재하지 않는 근거 ID를 반환하면 어떻게 대체 처리되는지 확인한다.

합성 분류 12건 중 11건 일치는 규칙 기준선의 결과다. 실제 모델 정확도나 현업 데이터의 일반화 성능이 아니다. 지시문이 섞인 사례 s11에서 규칙은 환불·결제를 모두 감지해 unknown으로 보류한다. 결과를 덜 멋지게 보이더라도 이 차이와 다음 개선 방법을 설명할 수 있어야 한다.

## 소통은 이렇게 확인한다

다른 세션에 `HANDOFF.md`와 `README.md`만 먼저 주고, 다음 명령과 남은 문제가 분명한지 확인한다. "다 됐다" 대신 실행한 명령, 결과, 확인하지 못한 경계, 다음 한 작업을 남긴다. 현재 포트·프로세스는 새로 확인하고, 키·개인 데이터는 문서에 넣지 않는다.

새 프로젝트에는 인수인계 양식이 자동 포함된다. 원본 키트의 증거가 복사되더라도 새 환경에서 실행됐다는 의미가 아님을 명시했다.

## 제출 전에 스스로 답할 질문

- 내가 정한 목표와 AI가 제안한 방법을 구분할 수 있는가?
- 왜 이 레포와 구조를 골랐는가? 더 복잡한 대안이 필요한 조건은?
- 실제 AI가 일한 곳, 규칙이 처리한 곳, 모의 처리가 어디인지 짚을 수 있는가?
- 실패 사례 하나를 재현하고 코드와 검증을 함께 바꿀 수 있는가?
- 다른 사람이 내 설명 없이 실행·검증·재개할 수 있는가?
