# 도메인을 바꿔도 재사용할 제품 구조

이 문서는 초기 공통화 설계와 확장 방향이다. 현재 구현·파일·동작·한계는 [HOW_IT_WORKS.md](HOW_IT_WORKS.md), 실제 실행 증거는 [VALIDATION.md](VALIDATION.md)를 기준으로 확인한다.

## 무엇을 공통으로 만들 것인가

범용성은 모든 도메인을 하나의 DB 테이블이나 만능 에이전트에 넣는 데서 나오지 않는다. 문제 해결 흐름과 시스템 경계를 재사용하고, 도메인의 원장·용어·규칙·정답 데이터는 별도 모듈로 둔다. 아래는 구현 목표이며 현재 구현된 서버 구조가 아니다.

```text
웹 / 모바일 / 데스크톱 / CLI
              ↓ 공통 API
업무 서비스: 접수 → 검증 → 처리 → 검토 → 실행 → 이력
              ↓ 선택된 어댑터
문서 파서 | 검색 | SQL/solver | 모델 | 외부 업무 시스템
              ↑ 도메인 팩
용어·입출력 형식·업무 규칙·권한·샘플·정답·평가
```

| 공통 모듈 | 재사용할 부분 | 도메인마다 바꿀 부분 |
|---|---|---|
| 입력·정규화 | 업로드, 형식/크기 검증, 작업 상태 | 파일 형식, 필수 필드, 단위 |
| 추출·분류 | 모델 호출, 구조 검증, 재시도 한도 | 분류표, 추출 필드, 예외 규칙 |
| 근거 검색 | 원문 위치, 검색 결과, 권한 필터 | 문서 집합, 최신성, 용어 |
| 계산·계획 | SQL/최적화 호출과 결과 검증 | 목적함수, 필수 제약, 업무 수식 |
| 검토·실행 | 초안, 승인, 취소, 중복 실행 방지 | 누가 무엇을 승인하는지, 외부 작업 |
| 기록·평가 | 실행 ID, 지연, 사용량, 오류, 기준선 비교 | 실제 성공의 정의와 정답 사례 |

AI가 유용한 곳은 비정형 입력 이해와 설명이다. 가격 합계·재고·예약 충돌·권한·금액 정산은 원장과 결정적 코드가 책임진다. 신뢰도가 낮다는 모델의 자기평가만으로 실행 권한을 주지 않는다.

## 플랫폼을 넘어가는 방법

- 업무 API와 입출력 형식을 먼저 고정한다. 클라이언트 안에 모델 키나 도메인 핵심 규칙을 복제하지 않는다.
- 웹은 React/Streamlit 중 목적에 맞는 하나, 모바일은 Expo/Flutter 중 팀 경험에 맞는 하나를 고른다.
- 데스크톱 파일 접근·마이크·카메라·알림·백그라운드 작업은 플랫폼별 어댑터와 권한 흐름을 갖는다.
- 로컬 실행은 Ollama 같은 어댑터 후보로 분리하되 모델 파일·라이선스·RAM·실제 지연을 먼저 확인한다.
- 배포 환경별 DB·스토리지·작업 큐는 설정으로 선택한다. 모든 어댑터를 미리 구현하지 않는다.

## 처음 제품화할 추천 범위

첫 통합 제품은 **접수 → 분류 → 근거 → 초안 → 승인 → 모의 실행**으로 좁힌다. 고객 지원·교육 행정·구매 요청·시설 관리에 같은 흐름을 적용해 재사용성을 검증하기 좋다. 첫 단계에서는 입력 데이터와 도메인 규칙만 바꿔 세 사례를 비교한다.

1. API 요청 ID와 사용자 범위가 있는 접수 기능.
2. Pydantic AI 또는 Vercel AI SDK 중 하나의 모델 어댑터.
3. 근거·누락 항목·제안 결과를 보여주는 검토 UI.
4. 승인된 내용에만 동작하는 모의 업무 어댑터.
5. 실제 사례 10개 이상과 실패 사례를 돌리는 평가.

상태는 `received → processing → needs_review → approved → executing → completed`로 두고 실패·취소를 별도 상태로 둔다. 승인·중복 방지·외부 작업 기록은 DB 트랜잭션과 외부 API 특성에 맞춰 구현한다. 메모리 플래그만으로 재시작 후 안전을 보장하지 않는다.

## 필요한 순간에만 추가할 것

- 문서 수와 검색 품질 문제가 생기면 pgvector와 검색 평가를 추가한다.
- 사람이 며칠 뒤 승인하는 장기 작업이면 영속 상태와 복구를 검토한다. LangGraph/Temporal은 이 필요가 확인될 때 선택한다.
- 외부 앱이 여러 개면 Activepieces 등을 검토하되 OAuth 계정·커넥터 권한·에디션을 확인한다.
- 반복 실행이 늘면 Langfuse 같은 관측 도구를 추가한다. 첫 데모에서는 구조화 로그로 시작할 수 있다.

## 80%를 측정하는 기준

기능 개수의 80%보다 **새 도메인 도입 때 재사용한 구현과 절약한 시간**을 측정한다. 도메인 3개에서 동일한 공통 흐름을 유지하고, 바꾼 코드·규칙·개발 시간·실패 사례를 기록한다. 공통화 때문에 예외 처리가 늘면 분리한다. 의료 판단·법률 결론·금융 의사결정처럼 정답 검증과 책임이 중요한 도메인은 별도 전문 검증이 필요하며 공통 구조만으로 해결 완료로 간주하지 않는다.
