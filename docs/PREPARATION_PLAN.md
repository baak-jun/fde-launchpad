# 범용 키트 구현과 검증 계획

요청 범위: 특정 행사·플랫폼·도메인에 묶이지 않는 FDE 준비물. 기존 조사와 조합표를 유지하고 실제 실행·복구·도메인 전환의 증거를 추가한다. 아래 항목은 계획이며 완료 표시에는 실행 증거가 필요하다.

1. 공통 실행 기반: 접수, 구조화 처리, 근거, 수정, 승인·거부, 실행 이력, 영속 저장, 중복 방지.
2. 도메인 전환: 고객 문의·시설 요청·구매 요청을 같은 코드와 서로 다른 도메인 팩으로 실행.
3. AI 어댑터: Pydantic AI를 재사용하고 규칙 대안·모의 모델·실모델을 명확히 구분. 호출 수·timeout 제한과 오류 기록.
4. 문제별 실행 예제: 문서 검색, 표 분석, 계획 최적화, 추천을 우선 실제 샘플로 검증. 음성·이미지·커머스는 필요한 모델/서비스의 설치·데이터 조건을 별도 기록하고 가능한 로컬 범위를 검증.
5. 플랫폼 경계: 같은 HTTP API의 브라우저·CLI 사용, 반응형 UI. 네이티브 장치 검증은 실제 장치 근거가 있을 때만 완료로 표시.
6. 실행 준비: 의존성 잠금, 진단·실행 명령, 소스 백업, 데이터 백업, 새 경로 복구 리허설.
7. 검증·인계: 정상/실패/권한/승인/중복 테스트, 도메인별 평가, 실제 화면 확인, 준비 상태 안내 갱신.

외부 계정·키가 없는 모델이나 서비스는 준비된 어댑터와 실제 연결 검증을 구분한다. 설치하지 않은 후보를 설치 완료로, 단위 테스트를 실제 도메인 성능 증거로 표시하지 않는다. 범용 제품의 재사용률 80%는 여러 실제 도입에서 측정하기 전까지 주장하지 않는다.

## 준비 키트 v1 완료 점검

1~2번은 로컬 업무 실험실과 3개 도메인 팩으로 구현했다. 3번은 실제 SDK의 TestModel, timeout·오류 대안·호출 예산을 검증했고 실제 모델 품질은 미검증이다. 4번은 네 실행 예제와 나머지 선택 구성의 도입 안내로 준비했다. 5번은 같은 API의 브라우저·CLI 및 좁은 화면을 확인했다. 6~7번은 잠금 파일·오프라인 번들·백업/복구·32개 테스트·설명과 인수인계 자료로 준비했다. 구체적인 결과는 [검증 기록](VALIDATION.md)을 기준으로 삼는다.

이 완료 범위는 다음 해커톤에서 문제를 골라 출발할 수 있는 준비 키트다. 실제 행사 문제, 실제 고객 데이터, 실모델, 외부 서비스 및 운영 배포는 그 프로젝트의 새 목표와 검증 대상으로 남는다.
