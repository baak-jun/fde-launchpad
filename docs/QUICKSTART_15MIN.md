# 15분 만에 사용하고 이해하기

## 0–3분 작동하는 흐름 보기

launch.cmd를 열고 http://127.0.0.1:8765 에 접속한다. 기존 서버가 있으면 그대로 사용한다. 고객 문의를 고르고 예제 → 초안 → 승인 → 로컬 기록을 눌러 본다. 여기서 실제 환불이 일어난 것은 아니며 이 기기에 승인한 초안이 저장된다.

## 3–6분 내가 통제하는지 보기

새 요청을 하나 더 만들고 승인한 뒤 입력을 수정한다. 실행 버튼이 사라지고 다시 검토 상태가 되는지 본다. 원인은 입력 수정 때 버전을 올리고 승인 기록을 지우기 때문이다. `runtime/store.py`의 revise와 execute를 열어 확인한다.

## 6–9분 도메인을 바꿔 보기

시설 요청과 구매 요청의 예제로 같은 순서를 반복한다. 달라지는 것은 domain_packs의 분류·정책·문구이고, 승인·기록·이력 코드는 그대로다. 실제 업무로 옮기려면 누가 어떤 기준으로 승인하는지와 원장 데이터를 추가해야 한다.

## 9–12분 AI의 경계를 설명하기

기본 분류는 규칙이다. 모델 연결 코드는 runtime/providers.py에 있다. SDK 테스트 모델은 호출 경로를 검증하지만 실제 언어 이해 성능을 검증하지 않는다. 아래 세 문장을 자기 말로 설명한다.

- 형식이 맞는 응답도 사실은 틀릴 수 있다.
- 키워드가 여러 분류에 걸리면 unknown으로 보류한다.
- 로컬 기록의 중복 방지는 외부 결제의 중복 방지를 보장하지 않는다.

## 12–15분 다음 프로젝트 시작하기

`python kit.py start my-first-fde`로 새 폴더를 만든다. BRIEF에 사용자·문제·성공 행동 하나를 적고 INTENT에 제약과 검증을 적는다. README의 설치·검증 명령을 실행한다. 다른 세션에 이어 맡길 때는 HANDOFF와 docs/SESSION_START.txt를 사용한다.

학습 후에는 templates/UNDERSTANDING.md의 질문에 코드 없이 답하고 실제 구현과 비교한다. AI가 작성한 설명을 읽은 것과 본인이 이해한 것은 구분한다.
