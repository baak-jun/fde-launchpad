# 목표와 결정 기록

## 2026-10-26 초기 준비

- 요청: 인증·레이아웃만이 아닌 여러 도메인 문제를 해결할 FDE 키트와 GitHub 후보를 미리 준비.
- 확인: 폴더는 .git만 있었고 커밋·사용자 소스가 없었다. 소스 ZIP 백업 방식을 추가.
- 결정: 모든 레포를 설치하는 대신 28개 후보와 8개 문제 조합을 먼저 정리.
- 근거: 플랫폼보다 데이터·업무 문제별 베이스가 다름. 라이선스와 현재 경로도 공식 원문에서 확인.

## 2026-10-26 범용 실행 기반

- 사용자 방향: 특정 행사 없이 범용으로 진행하고 계속 준비.
- 결정: 접수·검토·승인·실행을 공통으로 만들고 고객 문의·시설·구매를 JSON 팩으로 분리.
- 대안: 모든 서비스가 포함된 큰 템플릿, 여러 에이전트, 장기 워크플로 엔진. 현재 로컬 흐름에는 운영 부담이 커서 필요 시 도입할 후보로 유지.
- 재사용: FastAPI, Pydantic AI, SQLite, MarkItDown, DuckDB, OR-Tools. 도메인 연결과 작은 로컬 업무 상태만 직접 구현.
- 검증 계약: 승인 없는 실행 거부, 수정 후 승인 해제, 중복 기록 방지, 작업공간 격리, 재시작·복구, 모델 오류 대안.

## 실제 발견한 문제와 수정

- Windows의 기본 임시 폴더 ACL 때문에 venv의 ensurepip가 실패했다. 프로젝트 `.cache/tmp`를 사용해 재실행했다. setup.ps1에도 같은 경로를 반영.
- Pydantic AI 2.61.0에서는 결과의 usage가 메서드가 아닌 속성이었다. 테스트 모델 통합이 실패해 원인을 확인하고 `.usage()`를 `.usage`로 수정. 결과가 대안 모드가 아니라 테스트 모델 결과인지 검사.
- sandbox 안의 웹 서버에 브라우저가 연결하지 못했다. 기존 실행을 종료 확인한 뒤 로컬 loopback 서버를 허용된 외부 실행으로 띄워 확인. 공개 주소나 방화벽 설정은 변경하지 않음.
- 규칙 분류는 합성 12건 중 s11을 unknown으로 분류했다. 키워드가 여러 범주를 건드리는 한계를 평가 기록에 남겼다. 이를 모델 성능이나 완전한 업무 정답률로 포장하지 않음.

## 평가 기준 추가

- 사용자 제공: 기술·의도·인지 각 100점, FDE 소통 배점 미상.
- 갱신: 실행 코드뿐 아니라 목표·검증 계약, 실제 결정 기록, 본인 설명 연습, 다른 세션 인수인계 양식을 준비물에 추가.
- 유지한 제약: 특정 행사에 종속하지 않음, 변경 전 백업, 외부 계정·키 없이도 시작 가능, 검증 범위 구분.
- 작업 방식: 이번 구현은 한 에이전트가 수행했다. 여러 에이전트에 위임했다고 기록하지 않는다.
