# 주제가 정해졌을 때 추가할 구성

현재 실험실의 설치·테스트 완료와 아래 후보의 준비 조건을 구분한다. 아래 네 분야는 대형 모델·장치·업무 시스템을 임의로 기본 설치하지 않았다.

| 문제 | 베이스 | 먼저 확보할 것 | 첫 검증 | 대안 |
|---|---|---|---|---|
| 음성 | Whisper, 실시간이면 LiveKit Agents | 동의된 목표 언어 녹음, FFmpeg, 모델 크기·저장 공간, 실시간이면 STT/TTS와 전송 서버 | 알려진 문장 10개 전사, 무음·잡음·중단, 실제 지연 | 텍스트 입력과 합성 전사, 모의 표시 |
| 이미지 검사 | Anomalib | 도메인 정상·이상 이미지, 학습/검증 분리, 실행 장치, 모델 이용 조건 | 오탐·미탐과 도메인 밖 입력, 임계값 근거 | 사람이 판정한 샘플 결과로 UI만 시연 |
| 주문·재고 | Medusa / ERPNext | 실제 SKU·재고·가격의 원장, DB, 제품 에디션, 테스트 결제 키 | 읽기 전용 조회 후 품절·중복·승인 거부 | 현재 구매 요청 팩과 로컬 기록 |
| 모바일·데스크톱 | Expo / Flutter | 목표 OS·SDK·실기기, 마이크/카메라 등 권한 목록 | 같은 업무 API 호출 후 네트워크 중단·권한 거부 | 현재 반응형 웹; 네이티브 앱이라고 부르지 않음 |

각 후보의 공식 링크·라이선스·주의점은 [REPOSITORIES.md](REPOSITORIES.md)에 있다. 시작할 때 원문을 다시 확인하고 선택한 커밋·패키지 버전을 고정한다. 이 문서는 설치·실행 완료 증거가 아니다.

## 새 도메인 팩을 추가하는 순서

1. `domain_packs/support.json`을 새 ID의 파일로 복사한다.
2. 분류·키워드·정책·샘플을 실제 문제에 맞게 바꾸고 unknown 분류를 유지한다.
3. 정상·불명확·권한 밖·실패 사례를 추가한다. 정책이 있다는 것과 법적/업무적으로 맞는 것은 다르므로 담당자가 확인한다.
4. 전체 API 흐름과 평가를 실행한다. UI는 새 팩을 자동으로 표시한다.
5. 실제 원장·외부 작업이 필요하면 별도 어댑터와 승인·멱등 처리·실패 복구를 구현한다.
6. 변경 이유와 검증 결과를 INTENT/HANDOFF에 갱신한다.
